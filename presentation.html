The Challenge

Why Traditional Infrastructure Automation Fails

Modern cloud and hybrid datacenters are distributed, asynchronous, and unpredictable. Legacy tooling cannot keep up.

Brittle Linear Execution

Traditional bash runbooks and sequential scripts execute line-by-line. Independent tasks wait unnecessarily, blocking event loops and causing high remediation latency.

Cascading Catastrophic Failures

A failure in a non-critical step crashes the entire pipeline. There is no concept of dependency subgraphs, selective skipping, or isolated parallel survival.

Zero Real-Time Intelligence

Static regexes cannot parse unstructured stack traces or dynamic crash logs. Complex decision-making requires manual human triage at 2 AM.

Fragile Glue Code & Temp Files

Pipelines rely on temporary files, fragile sed/awk scripts, and unvalidated environment variables that break across host operating systems.

Our Solution: A declarative, JSON-driven DAG orchestrator with async concurrency, failure isolation, and integrated AI.
System Architecture

End-to-End Orchestrator Pipeline

1. Ingestion & Validation
  • • FastAPI Ingestion: Ingests JSON DAG payload via POST /workflows.
  • • Kahn's Validation: Validates zero duplicate IDs and cycles in $O(V+E)$ upfront.
  • • 202 Accepted: Returns UUID workflow_id immediately; dispatches to BackgroundTasks.
2. Async Parallel Engine
  • • In-Degree Scheduler: Zero in-degree nodes launch concurrently with asyncio.create_task.
  • • Threaded Subprocesses: Wrapped in asyncio.to_thread to maintain event-loop responsiveness.
  • • Context Engine: In-memory context accumulater for inter-step variable passing.
3. Telemetry & Web UI
  • • Live State Polling: Clients poll GET /workflows/{id} at 500ms intervals.
  • • Visual DAG Canvas: Real-time node color transitions on vis-network.
  • • Inspector: Instant stdout, stderr, JSON response, and skip reason review.

Concurrency Core

Asynchronous Parallel DAG Scheduling

Kahn's Algorithm Validation

Calculates in-degree for every step. Guarantees complete DAG determinism and catches circular dependencies before scheduling any task.

Dynamic Parallel Fork-Join

When Node A succeeds, both Node B and Node C launch in parallel concurrently. Node D automatically joins only when both dependencies succeed.

Non-Blocking Worker Dispatch

Heavy I/O (REST, AI API calls) use native async httpx. Shell subprocesses run via asyncio.to_thread to prevent Windows event loop blocks.

// Dynamic Scheduling Loop (engine.py)
while True:
    # Launch all ready zero in-degree tasks
    for sid, step in step_map.items():
        if results[sid]["status"] == PENDING:
            if all(results[d]["status"] == SUCCESS for d in deps[sid]):
                task = asyncio.create_task(execute_step(step, context))
                running_tasks[sid] = task

    if not running_tasks: break

    # Reactive resolution on task completion
    done, _ = await asyncio.wait(
        running_tasks.values(), 
        return_when=asyncio.FIRST_COMPLETED
    )
Fault Tolerance

Granular State Machine & Failure Isolation

PENDING
Awaiting deps
RUNNING
Active execution
SUCCESS
Output in context
FAILED
Error recorded
SKIPPED
Branch deactivated

Recursive Subgraph Deactivation

When a step fails, the BFS traversal function _mark_descendants_skipped cascades SKIPPED only to dependent descendants. Each skipped node receives a precise diagnostic error explanation.

Independent Branch Survival

Parallel branches that do not depend on the failed node proceed unaffected to complete execution. Unlike monolithic scripts, partial failures never crash isolated operations.

Data Flow

Dynamic Context Engine & Variable Passing

Steps seamlessly pass data between nodes without temporary disk files or environment variables. Outputs are captured in a shared runtime context and interpolated dynamically before step execution.

Supported Interpolation Syntax:
  • • ${{ steps.FetchAuth.stdout }} (Shell Output)
  • • ${{ steps.GetStatus.response.args.env }} (REST JSON)
  • • ${{ steps.AiTriage.response.severity }} (AI Extraction)
  • • ${{ steps.FilterJQ.response[0].id }} (JQ Arrays)

Strict JSON Schema Enforcement

Data Reshaping

JQ Transformation Node (type: "jq")

In-Memory C-Speed Filtering

Powered by native jq compiling. Reshapes, slices, filters, and aggregates complex JSON payloads entirely in-memory without spawning external python or bash scripts.

Thread-Safe Async Dispatch

JQ transformations run via asyncio.to_thread, ensuring compute-heavy JSON queries do not block the FastAPI event loop.

Payload Schema Normalization

Bridges disparate REST microservices by converting upstream response formats into the exact request structure expected by downstream endpoints.

Dynamic Branching

Safe AST Conditional Node (type: "condition")

Zero Unsafe Code Execution

Evaluates boolean expressions using Python's ast module. Function calls, arbitrary imports, and malicious injections are strictly blocked.

Dual Configuration Syntax

Supports full Python expressions (e.g. '${{ ... }}' == 'APPROVE' and count > 0) or structured operands (left, operator, right).

Automatic Type Coercion

Intelligently handles string-to-number and string-to-boolean coercion (e.g., comparing string "200" to int 200).

// Example Condition Configuration
{
  "id": "CheckRestartNeeded",
  "type": "condition",
  "config": {
    "expression": "${{ steps.AiTriage.response.requires_restart }} == true"
  },
  "depends_on": ["AiTriage"]
}
